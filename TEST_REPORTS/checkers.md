# 跳棋规则验收报告

测试基准为经典六角星中国跳棋：121 个棋位，2–6 人，每方 10 枚棋子；相邻移动或跳过任意颜色棋子，允许连续跳跃并主动结束；全部棋子进入对角目标角后获胜；跳棋不吃子。

## 规则对照

| 规则项目 | 验收结果 |
| --- | --- |
| 121 个棋位、六角星棋盘 | 通过 |
| 2–6 人布置和每方 10 枚棋子 | 通过；2、3、4、5、6 人均创建并检查初始棋子数 |
| 相邻移动 | 通过 |
| 跳过任意颜色棋子 | 通过；规则攻击局验证了跳过对手棋子 |
| 连续改变方向跳跃 | 引擎支持；规则攻击局实际验证连续跳跃流程 |
| 连跳中途主动结束 | 通过 |
| 不吃子、棋子不消失 | 通过；三局及随机回归始终保持 20 枚（2 人） |
| 对角目标角获胜 | 通过；三局均自然产生胜者 |
| 越权、越界、非整数、未选子和终局后动作 | 通过；均被服务器拒绝且状态不变 |

## 三局完整对局

三局都从正常创建 Room、加入两名玩家并调用 `Room.startGame()` 开始，所有成功动作都经由 `Room.handleGameAction()`，没有修改引擎棋盘或回合状态。完整动作序列由 [`scripts/checkers-acceptance.js`](../scripts/checkers-acceptance.js) 生成到未纳入 Git 的 [`artifacts/checkers-acceptance-runs.json`](./artifacts/checkers-acceptance-runs.json)；它是可选复现工件，不是运行时依赖。

1. 正常局：134 个完整回合，乙方获胜；覆盖相邻移动、跳跃、目标角结算。
2. 规则攻击局：127 个完整回合，甲方获胜；开局执行合法的两次连续跳跃并返回原位后主动结束，随后验证跳过对手棋子和终局。
3. 固定种子合法策略随机局：种子 `0x5eed1234`，129 个完整回合，甲方获胜；每次动作均从服务端当前合法操作中产生，并可用同一动作序列重放。

## 状态不变量与回放

三局和随机回归逐步检查：

- 棋子坐标均属于 121 个棋位且互不重叠；
- 两方棋子数始终为 10，跳跃不产生吃子；
- 选择/连跳中途不提前改变公共棋盘、不提前计回合；
- 完整移动后正确切换行动方，终局后拒绝继续操作；
- 当前玩家才拥有选择和移动入口，所有合法目标在棋盘内且为空；
- 状态可 `JSON.stringify()` 序列化；保存的完整动作序列可重放得到相同终局状态。

额外运行 100 局固定种子的“合法策略随机”对局，全部自然结束，长度 127–159 回合。该组测试为从合法候选中随机选择并使用目标距离避免无意义循环，不能等同于完全均匀随机。

## 严格均匀随机局结果

按验收要求，使用种子 `0x5eed1234` 在每回合从服务端合法选择中均匀随机选取，连续运行 10,000 个完整回合并逐步检查状态不变量。棋局仍为 `playing`，没有胜者。

因此，“完全均匀随机局必须在上限前自然结束”这一项目前不能标记为通过。动作本身全部合法，没有发现状态损坏；原因是跳棋允许来回移动，而当前基础规则没有重复局面或无进展和棋判定。没有擅自把非标准的回合上限或和棋规则加入引擎。

## 双客户端协议验收

通过两个隔离 WebSocket 客户端完成：

- 大厅游戏列表包含 `checkers`，房间按 2 人正常创建和开始；
- 双方身份、颜色、公共棋盘和回合同步；
- 当前客户端能看到自己的选择，对手客户端的 `selectedPiece` 保持为空；
- 非当前玩家的动作被服务器拒绝；
- 连跳、移动后的双方状态一致；
- 主客户端断线后使用会话令牌重连，玩家身份、棋局进度和棋盘恢复正确。

## 结论

跳棋的基础规则、2–6 人设置、三局完整策略对局、100 局合法策略随机回归、状态不变量、动作重放和双客户端协议均通过。严格验收唯一未通过项是完全均匀随机局在 10,000 回合内没有自然结束；这更像是随机策略与规则没有重复和棋判定的组合限制，而不是非法移动或状态机错误。若要让“完全均匀随机”也能通过，需要先决定是否采用重复局面/无进展和棋规则。
