# 第四阶段：浏览器运行时回归、性能与清理门禁

测试日期：2026-08-29
测试版本：`2.1.0`（第四阶段未发布增量）

## 结论

本阶段自动化运行时回归通过。24 款非 3D 游戏在统一视觉夹具中按桌面、竖屏和两档短横屏执行 96 次加载/渲染检查，96/96 通过，浏览器运行时错误 0。28 个正式客户端模块的 Firefox 动态导入检查也为 28/28；同一门禁现已用两个独立标签完成公开房间列表、五子棋创建/加入/准备/开局/核心落子、传输断线后自动重连恢复原座位、刷新恢复原座位与对局、成员离开和房间清理，并验证仅邀请房间不出现在公开列表、仅凭房间号会被拒绝、带随机令牌的邀请链接可以加入。离开流程还确认已离开的标签清空游戏挂载点和客户端实例；隐藏身份、花火牌背、谍报风云密钥在 Firefox 视口中也通过隐私与输入收束检查。

这批结果证明重构后的模块能在浏览器中完成加载、状态注入、基础交互和尺寸收敛；它不替代真实玩家使用多浏览器、多标签和真实 WebSocket 对局的最终签字。

## 可重复命令

项目新增浏览器回归命令：

```bash
npm run test:browser
```

可选 Chromium 复核（需要本机提供浏览器可执行文件）：

```bash
CHROMIUM_BIN=/path/to/chromium npm run test:browser:chromium
```

命令会在当前 Node 进程中启动临时 HTTP/WebSocket 服务，启动临时无头 Firefox WebDriver BiDi 会话，完成以下检查后自动清理临时资源：

1. 导入 28 个客户端模块（24 个普通客户端、环城大富翁客户端、国际象棋大厅桥接器、军棋、中国象棋）。
2. 用两个独立浏览器标签完成公开房间列表、五子棋创建、加入、取消准备/重新准备、开局、核心落子；由测试服务端主动终止成员 WebSocket 以模拟传输断线，确认房间暂停、成员凭短期会话令牌自动重连并恢复原座位，再完成刷新后的会话恢复、成员离开和房主清理房间；离开后检查游戏挂载点为空且客户端数据属性已移除；再验证仅邀请房间隐藏于公开列表、拒绝仅凭房间号加入并允许带随机令牌的邀请链接加入。
3. 使用 `public/__game_shell_visual_test.html` 渲染 24 款非 3D 游戏。
4. 对每款游戏检查 `1280×900`、`390×844`、`667×375`、`844×390` 四档视口。
5. 收集 `window` 级 `error`/`unhandledrejection`，并检查统一外壳的核心区域、离开按钮、短横屏可见性和滚动边界。
6. 在 `390×844` 视口模拟空格/Enter 按住、触屏指针按住、松开和窗口失焦，确认狼人杀、阿瓦隆、猎巫镇和政变的身份牌始终按需显示并及时封存；同时确认花火只给本人渲染牌背、队友渲染正面，谍报风云的关键词/密码在键盘、触屏和失焦后重新隐藏。

运行环境需要能够执行 `firefox`；可用 `FIREFOX_BIN=/path/to/firefox npm run test:browser` 指定浏览器路径。

## 第三批：性能预算、并发烟测与资源清理

新增 `npm run test:performance`，在临时 HTTP/WebSocket 服务中执行固定上限的性能与清理检查：

1. 检查首屏、主脚本、主样式、Three.js 和 `public/` 首方源码总量是否超过预算；当前分别为 `17181/24576`、`58688/143360`、`98905/163840`、`650153/716800` 和 `3296209/3774873` bytes（首方源码 286 个文件）。
2. 并发请求 6 类代表性资源共 40 次，当前 `40/40` 返回 200，最近运行最大本地响应延迟为 `39.3ms`（门禁 `1500ms`）。
3. 短时创建 20 个大厅客户端并主动关闭，确认观察者收到连接数从 21 回收至 1。
4. 并发创建 6 个公开五子棋房间、加入 6 名成员，再依次离开，确认 6 个房间和 12 个玩家均被回收；本地烟测总耗时通常低于 `1s`。

这是一条有界本地烟测，用于阻止资源意外膨胀、静态服务回退和房间/连接泄漏；它不等同于生产容量压测，生产容量仍需在预发布环境按真实机器规格、网络和并发目标执行。

## 第五批：网络断线与发布纪律自动化

本批将两项仍依赖人工的前置检查收敛为可重复的本地门禁：

- Firefox 双标签生命周期会由临时服务端主动 `terminate()` 成员连接，确认房间进入暂停态，浏览器在 30 秒宽限期内自动携带会话令牌重连，原玩家 ID、席位和对局视角保持不变，房间随后恢复；这是真实 WebSocket 传输中断的自动化模拟，不是浏览器 DevTools 的 `offline` 假象。
- 新增 `npm run test:release`，检查 `package.json` 与 `package-lock.json` 版本同步、必需门禁脚本、systemd/Nginx 本机反代与最小权限模板、`.gitignore` 规则，以及 Git 跟踪文件中没有 `tmp/`、环境变量、密钥或日志。

本机本批结果：`transport reconnect: PASS`，`npm run test:release` 通过；发布纪律检查已接入 GitHub Actions。真实移动设备、多浏览器人工签字、HTTPS/安全组和预发布服务器仍需目标环境完成。

## 第 4 批：生产形态启动、健康检查与优雅停机

新增 `npm run test:deploy` 作为不接触外部基础设施的预发布前置烟测。脚本使用生产环境变量启动实际 `bin/www`，轮询 `/healthz` 确认服务版本与实时状态，校验 CSP、`X-Content-Type-Options`、`X-Frame-Options`、`Cache-Control` 等响应头；随后以显式 Origin 建立真实 WebSocket、创建并离开一个房间，最后发送 SIGTERM，要求进程在限定时间内以状态码 0 退出。该门禁已纳入 `npm run test:acceptance` 和 `npm run test:release` 的必需文件/脚本审计。
