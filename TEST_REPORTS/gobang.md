# 五子棋核心验收报告

## 验收基准

按本项目当前需求，以经典 15×15 五子棋为基准：黑方先手，双方轮流落子，横、竖、斜线连续五子即胜；不考虑三三、四四等禁手，长连也算胜利；棋盘填满且没有胜者时和棋。人数固定为 2 人，不纳入棋钟、悔棋、认输、AI 和竞技积分。

## 规则对照

| 规则项目 | 服务端实现 | 验收结果 |
| --- | --- | --- |
| 15×15 棋盘 | `GobangEngine.BOARD_SIZE = 15` | 通过 |
| 黑方先手、双方交替 | `turn`、`currentTurnIndex` | 通过 |
| 落子必须在棋盘内且为空位 | `inside()`、`board.has()` | 通过 |
| 横、竖、正斜、反斜五连 | `_hasFive()` 四方向扫描 | 通过 |
| 不设禁手 | `forbiddenMoves: false`，双三局面可落子 | 通过 |
| 长连获胜 | 连续数量使用 `>= 5` | 通过 |
| 满盘和棋 | 棋盘达到 225 格后结算 | 通过 |
| 终局后拒绝继续落子 | `status !== 'playing'` 直接拒绝 | 通过 |
| 两人房间限制 | 元数据 `minPlayers/maxPlayers = 2`，Room 层校验 | 通过 |

## 三局完整对局

三局都从正常创建 Room、加入两名玩家并调用 `Room.startGame()` 开始，未修改引擎棋盘或回合状态，所有着法均由服务端合法动作产生，并保存于 [`gobang-acceptance-runs.json`](./gobang-acceptance-runs.json)。

1. 正常局：9 手，黑方横向五连获胜。
2. 规则攻击局：21 手。黑方先完成一个双三局面，因不设禁手被接受；随后填入中间空位形成六连，黑方获胜。
3. 固定种子随机局：种子 `0x5eed1234`，112 手，白方获胜。

另外使用无五连构造自然填满 225 格，满盘和棋通过。

## 状态不变量与回放

- 每一步棋子坐标唯一、均在棋盘内，棋子数与 `moveNumber` 一致：通过。
- 已落子不会消失或改变，当前行动方交替正确：通过。
- 当前玩家合法位置完整且全部为空，非当前玩家不获得落子列表：通过。
- 越界、非整数、错误动作、非当前玩家、重复落子和终局后动作：均被拒绝且状态不变。
- 相同着法在新会话中重放得到完全相同的终局状态：通过。
- `JSON.stringify(getPublicState())` 可序列化：通过。
- 显式 `serialize()/restore()` 接口：未实现。当前只能通过保存着法并从初始局面重放恢复，因此按严格验收标准记为“部分通过”。

## 固定种子随机回归

额外运行 100 局合法随机对局，种子为 `0x5eed0000` 至 `0x5eed0063`。全部自然结束，无超出 225 手或状态卡死；对局长度 48–161 手，和棋 0 局。

## 双客户端协议验收

使用两个隔离 WebSocket 客户端通过真实房间协议完成一局，房间号 `000003`：

- 服务端下发的 27 款游戏列表包含 `gobang`。
- 黑、白双方视角和 `myColor` 正确，只有当前玩家拥有合法落子列表。
- 非当前玩家操作、重复提交均被服务器拒绝。
- 合法落子被双方同步，双方棋子状态一致。
- 白方断线后使用会话令牌重连，棋盘、回合和玩家身份恢复正确。

本次自动验收覆盖真实 WebSocket 房间协议，未接入浏览器自动化来模拟 DOM 点击和 CSS 落子动画；五子棋当前只有 2D 客户端，因此 2D/3D 切换不适用。浏览器级点击与动画仍建议人工补验。

## 结论

五子棋核心规则、三局完整对局、100 局固定种子随机对局、状态不变量和双客户端流程均通过。严格按照此前验收标准，代码层唯一未完成项是显式的服务端状态恢复接口；不影响当前正常对局，但若要达到“序列化—恢复—重放”全部通过，后续应为引擎补充正式快照/恢复 API。浏览器 DOM 点击和动画还需要人工补验。
